# SA — аудит и исправление безопасности для Claude Code и Codex

Один скилл **`sa`**: проверка эндпоинтов, исправление подтверждённых замечаний или полный цикл. Каждый этап проверки выполняют новые сабагенты с чистым контекстом; данные и история находятся в `Security Audit/` текущего проекта. Логика не зависит от среды; механизмы запуска ролей, таймеров и инструкций проекта описаны в адаптерах [Claude Code](references/platform-claude-code.md) и [Codex](references/platform-codex.md).

## Установка

Нужны Claude Code или Codex с локальными скиллами и Python 3.9+. Python-пакеты, API-ключи и внешние сервисы для установки не требуются. На macOS и Linux команда — `python3`, на Windows — `python`.

macOS / Linux:

```bash
git clone https://github.com/GeorgVahi/SA.git
cd SA
python3 scripts/install.py --platform claude
```

Windows (PowerShell):

```powershell
git clone https://github.com/GeorgVahi/SA.git
cd SA
python scripts/install.py --platform codex
```

`--platform` обязателен: `claude` ставит в `~/.claude/skills/sa`, `codex` — в `~/.agents/skills/sa`. Это глобальная установка для текущего пользователя и всех его проектов. Для Claude Code не копируются UI-метаданные Codex (`agents/openai.yaml`). Другой каталог скиллов задаётся `--skills-dir`, например `--skills-dir "$env:USERPROFILE/.codex/skills"`. Устанавливайте в один обнаруживаемый каталог на среду, чтобы не получить дубликаты; для обеих сред запустите установщик дважды.

Установщик копирует только файлы скилла и сохраняет manifest. Существующий скилл не перезаписывает. Обновление установленной этим скриптом версии:

```bash
git pull --ff-only
python3 scripts/install.py --platform claude --update
```

Используйте те же `--platform` и `--skills-dir`, что при установке; поверх установки другой среды обновление не пишет. При ручных изменениях, неизвестных файлах или конфликте «файл ↔ каталог» обновление останавливается до записи: сначала сохраните и согласуйте свои правки или миграцию структуры. Неуспешное I/O-обновление не считается установленной версией; сверяйте файлы перед повтором. Скрипт не меняет настройки среды, модели, разрешения или Git-конфигурацию.

Прежние версии назывались `SA` и ставились в `~/.agents/skills/SA`. `--update` с `--platform codex` переименует управляемую установку в `sa`, в том числе на файловых системах без различения регистра. Вызов в Codex меняется с `$SA` на `$sa`. Имя `sa` соответствует стандарту Agent Skills (lowercase, совпадает с каталогом).

Откройте чат в нужном проекте и введите `/sa` (Claude Code) или `$sa` (Codex). Если скилл не появился, перезапустите приложение. Документация: [скиллы Claude Code](https://code.claude.com/docs/en/skills), [скиллы Codex](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills).

## Использование

| Запрос | Результат |
| --- | --- |
| `/sa audit`, `$sa audit` | Полный инвентарь с независимой проверкой, аудит и независимое ревью каждого эндпоинта; приложение не исправляется |
| `/sa fix`, `$sa fix` | Актуализация записанных замечаний и четыре роли для каждого исходного файла: план → ревью плана → внедрение → ревью кода |
| `/sa full`, `$sa full` | Аудит → исправления принятых находок → повторный аудит затронутых эндпоинтов на конечном коде |
| `/sa продолжи существующий запуск` | Восстановление выбранного режима, очереди, версий, владельцев и накопленного времени |

После команды режим можно описать естественной просьбой. В Claude Code скилл запускается только командой `/sa` (`disable-model-invocation`): просьба «проведи аудит безопасности» без неё скилл не запустит, а роли не могут вызвать его сами. Этот ключ относится к Claude Code; в Codex скилл, как и раньше, вызывается `$sa` или однозначной просьбой. При одном `/sa` или `$sa` скилл задаёт один вопрос с тремя вариантами; до ответа приложение не меняется. Явно выбранный режим не требует повторных подтверждений обычного локального плана и патча. Это инструкции агента, а не отдельные CLI-команды. В Claude Code число параллельных линий можно указать в просьбе (например, `/sa fix, 6 линий`); по умолчанию их 4.

При повторном аудите инвентарь снова сверяется с текущим кодом. Reuse возможен только при принятом прежнем ревью и доказанном совпадении всей влияющей dependency closure, bytes на диске, контракта доступа и внешних условий. Его подтверждает новый ревьюер. Commit SHA и неизменившийся handler сами по себе недостаточны.

## Claude Code: перед первым запуском

- **Разрешения.** Роли работают в фоне, и запрос разрешения ждёт ответа в основной сессии; в режимах без диалога роль получает отказ молча и возвращает blocked. Перед запуском координатор перечисляет нужные разрешения: чтение `~/.claude/skills/sa`, `python3`, тестовые команды проекта, фоновый `sleep` для таймера часовой сводки, запись в `Security Audit/` и, для fix/full, в исходники. Включите auto mode или добавьте allowlist в `.claude/settings.local.json` проекта.
- **Рекомендуемые ограничения** (действуют на всю сессию, поэтому скилл их не включает): `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` — роли не запускают своих агентов; `CLAUDE_CODE_FORK_SUBAGENT=0` или deny `Agent(fork)` — роль не унаследует историю координатора; `/sandbox` — Bash без сети и записи вне проекта; deny для WebFetch, WebSearch и MCP на время запуска. Координатор сообщает, какие из них не подтверждены. Deny-правила Bash сравнивают начало команды и обходятся другой её формой (`git -C <путь> log` вместо `git log`), поэтому ограничением роли не считаются.
- **Инструкции и агенты вне проекта.** Роли получают не только инструкции проекта, но и `CLAUDE.md`/`AGENTS.md` каталогов-предков и `~/.claude/CLAUDE.md`; координатор называет их до первой роли, исключить их можно настройкой `claudeMdExcludes`. Агент с `name: general-purpose` в `.claude/agents/` проекта или в `~/.claude/agents/` подменяет роль, поэтому координатор останавливается на blocker до вашего решения.
- **Долгие запуски.** Сон Mac, закрытие приложения и лимит тарифа останавливают роли; продолжение — `/sa продолжи`. Для многочасового `full` держите Mac бодрствующим (настройка desktop-приложения или `caffeinate -i`). Часовые сводки приходят, пока сессия открыта.
- **Конфиденциальность.** Транскрипты сессии и ролей хранятся в `~/.claude/projects/` и содержат находки. Скилл не сохраняет находки в memory, Artifact, коннекторах и уведомлениях.
- **Форматы.** Текстовые источники в любых кодировках обрабатываются стандартным `python3`. Для записи результата в PDF, Office-документы и сканы нужны установленные инструменты (например, pypdf, openpyxl, LibreOffice); скилл их не ставит, а без проверенного writer оставляет конкретный blocker.
- **Стоимость.** В desktop-приложении контекст роли ещё до чтения скилла — около 50 тыс. токенов: системный prompt и описания инструментов (замер на Claude Code 2.1.295). Затем роль заново читает `SKILL.md` и 3–5 references (до ~120 КБ текста), а каждый следующий вызов модели внутри роли перечитывает весь контекст из кеша. Fix на N файлов — минимум 4N ролей.

## Исправления и приёмка

`fix` читает все файлы Endpoint Reviews рекурсивно. Старые Profiles/Tasks/Reviews сохраняются и получают связанные документы для исправления. Формат и кодировка не ограничивают область: для текстов, PDF/офисных документов, структурированных файлов, сканов, контейнеров и других типов выбирается подходящий доступный обработчик. Результат записывается в тот же исходный файл с сохранением несвязанных данных и проверкой повторного чтения. Реальное препятствие чтения/сохранения явно отражается в очереди; отдельный отчёт не подменяет незавершённую запись источника.

Первый агент перепроверяет реальность замечаний и пишет план. Второй независимо проверяет и при необходимости дополняет его новой версией. Третий внедряет принятый план и необходимые regression checks. Четвёртый не пишет код приложения: самостоятельно проверяет результат и записывает статус, доказательства и оценку 1–10. Already-resolved и rejected требуют доказанного независимого подтверждения; фиктивный патч для них не создаётся.

Статус устранения определяется доказательствами, актуальным независимым вердиктом и успешными обязательными проверками. Числового порога нет; оценка описывает качество отдельно. Локальный resolved не означает выполненный production-rollout.

Разные файлы обрабатываются параллельно по фактическим слотам; запись общей зависимости сериализуется. Один общий дефект исправляется один раз, но применимость к каждому исходному файлу подтверждается свежими ролями. Канонический issue закрывается после подтверждения всех затронутых endpoint-контекстов.

Общего лимита продуктивных попыток нет. Три последовательных раунда без доказанного продвижения вызывают независимую переоценку; при новом обоснованном пути работа продолжается, иначе сохраняется blocker. Смена агента и косметические изменения не считаются прогрессом. Checkpoint предотвращает потерю очереди, истории и повторный запуск конкурирующих писателей.

## Что проверяется

Все 12 категорий: IDOR/авторизация, инъекции, SSRF, файлы, вебхуки, CSRF, секреты, платежи, повторы, гонки, входы и лимиты. Каждая категория имеет доказательство выполненной проверки, основание неприменимости или конкретный blocker. Задачи создаются только по доказанной достижимой цепочке нарушения контракта; например, само поле owner не доказывает запрет общего чтения.

## Результаты

```text
Security Audit/
  Endpoints.md, Inventory Review.md
  State.json, Summary.md
  Profiles/, Fingerprints/, Tasks/, Reviews/
  Endpoint Reviews/                 исходные документы по эндпоинтам
  Remediation/<run-id>/
    Plans/, Plan Reviews/, Implementations/, Code Reviews/, Snapshots/
  Remediation Summary.md
```

Прежние поля checkpoint сохраняются при переходе к schema 2; формат fingerprint-helper остаётся отдельным. История запусков/версий не перезаписывается. Финальная сводка fix/full охватывает каждый исходный файл, одна строка на замечание:

| Файл | Эндпоинт | Замечание | Оценка |
| --- | --- | --- | --- |

Статус и ссылка на ревью входят в описание замечания. Файлы без записанных findings имеют отдельную строку и оценку —. Дубликаты показаны во всех источниках, но уникальные задачи считаются один раз.

Каждый час активной работы сообщается прогресс, остаток файлов/уникальных задач, blockers и ETA диапазоном по реальным замерам и фактической параллельности. Обычные краткие updates сохраняются. Продолжение восстанавливает время. Для отдельно запрошенной доставки при неактивном чате нужен таймер или heartbeat среды (см. адаптер); скилл и установщик не создают постоянный процесс вне сессии.

Недоступная независимая роль, stale версия, провал обязательной проверки или blocker дают честный частичный результат и очередь. Аудит с найденной уязвимостью может быть завершён; исправления — только после доказанного результата всех задач. Full дополнительно подтверждает актуальность полного аудита на конечном коде.

## Границы доступа

Безопасные локальные проверки и синтетические данные. Production, реальные платежи/вебхуки, чужие данные, разрушительные миграции, новые production-зависимости/инфраструктура и выход за полномочия требуют соответствующего разрешения. Секреты и персональные данные не выводятся. Публикация отчётов об уязвимостях требует явной авторизации именно на находки; обычного git autopublish недостаточно. Внешние worktree не создаются. Скилл не гарантирует обнаружение всех возможных уязвимостей.
