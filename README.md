# SA — Security Audit для Codex

Скилл для полного аудита эндпоинтов проекта. Вызов: **`$SA`**.

SA сначала проверяет документацию и существующую папку `Security Audit`, составляет или дополняет `Endpoints.md`. Новый сабагент с чистым контекстом независимо проверяет полноту списка. Затем каждый эндпоинт проходит аудит и независимое ревью двумя разными свежими сабагентами. Результат — профиль каждого эндпоинта и отдельные задачи только для подтвержденных проблем. Код приложения не меняется.

## Установка на ПК

Нужны Codex с локальными скиллами и Python 3.10+. Python-пакеты, API-ключи и внешние сервисы для установки не требуются.

```powershell
git clone https://github.com/GeorgVahi/SA.git
cd SA
python scripts/install.py
```

По умолчанию устанавливается в `~/.agents/skills/SA`, глобально для текущего пользователя и всех его проектов. Если ваша версия/конфигурация Codex использует другой каталог скиллов:

```powershell
python scripts/install.py --skills-dir "$env:USERPROFILE/.codex/skills"
```

Устанавливайте в один обнаруживаемый каталог, чтобы не получить дубликаты. Установщик копирует только файлы скилла и сохраняет manifest. Существующий скилл не перезаписывает. Обновление установленной этим скриптом версии:

```powershell
git pull --ff-only
python scripts/install.py --update
```

Используйте тот же `--skills-dir`, если меняли каталог. При ручных изменениях, неизвестных файлах или конфликте «файл ↔ каталог» обновление останавливается до записи: сначала сохраните и согласуйте свои правки или миграцию структуры. Неуспешное I/O-обновление не считается установленной версией; сверяйте файлы перед повтором. Скрипт не меняет `config.toml`, модели, разрешения или Git-конфигурацию.

Откройте чат в нужном проекте и введите `$SA`. Если скилл не появился, перезапустите Codex. Локальные скиллы и их обнаружение описаны в [официальной документации](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills). Имя `SA` сохранено в верхнем регистре для точного вызова `$SA`; типовой валидатор skill-creator требует lowercase, поэтому проверка имени этим валидатором не проходит. Обнаружение имени проверяется реальным `skills/list` Codex, остальные поля — отдельной проверкой структуры.

## Использование

```text
$SA Проведи полный аудит всех эндпоинтов этого проекта.
```

```text
$SA Продолжи существующий Security Audit и перепроверь изменившиеся эндпоинты.
```

При повторном запуске инвентарь снова сверяется с текущим кодом. Прежний результат переиспользуется только при принятом ревью и доказанном совпадении обработчика, регистрации, авторизации, сервисов, схем, ограничений данных и остальных влияющих зависимостей. Commit SHA и неизменившийся файл обработчика сами по себе недостаточны. Решение о переиспользовании тоже проверяет новый независимый ревьюер.

## Что проверяется

IDOR/авторизация, инъекции, SSRF, файлы, вебхуки, CSRF, секреты, платежи, повторы, гонки, входы и лимиты. В каждом профиле есть результат всех 12 категорий с доказательствами или основанием неприменимости. Недоступная проверка отмечается как blocker, не как успешный аудит.

Задача содержит файл и строки, достижимый сценарий атаки, права атакующего, последствия, выполненные и предлагаемые проверки, ожидаемое поведение, исправление и независимое ревью. Доказательство — безопасное локальное воспроизведение или полная проверяемая цепочка по исходникам. Теоретические гипотезы не становятся задачами.

## Результаты

```text
Security Audit/
  Endpoints.md            полный инвентарь
  Inventory Review.md     независимая проверка списка
  State.json              очередь и checkpoint
  Summary.md              итог и ограничения
  Profiles/               профиль каждого эндпоинта
  Fingerprints/           хеши проверенного кода и зависимостей
  Tasks/                  отдельные подтвержденные проблемы
  Reviews/                независимые решения и раунды исправлений
```

Параллелизм ограничивается фактически свободными слотами, включая координатора и вложенных агентов. Разные эндпоинты проверяются параллельно; аудит и ревью одного эндпоинта всегда последовательны. Общие файлы меняет координатор, чтобы агенты не конфликтовали.

Если среда поддерживает goal mode, SA использует его до завершения покрытия. Каждые 2 часа активной работы сообщает число принятых эндпоинтов, уникальных проблем и критических, остаток и оценку времени по реальным замерам. Checkpoint позволяет продолжить после прерывания. Для доставки при неактивном чате нужен отдельно доступный thread-heartbeat; сам файл скилла не запускает постоянный фоновый процесс. Установщик не создает автоматизацию.

При отсутствии чистых сабагентов, лимитах или недоступной проверке SA сохраняет частичный результат и очередь. Полное завершение возможно только после актуального принятого профиля каждого эндпоинта. Найденные уязвимости остаются задачами: завершение аудита не означает исправление приложения.

## Границы доступа

SA анализирует текущий проект и выполняет безопасные локальные проверки. Production-запросы, реальные платежи, чужие данные и публикация security-отчетов требуют отдельного разрешения. Секреты и персональные данные в отчеты не попадают. Обычный автоматический commit/push проекта не разрешает публикацию найденных уязвимостей. Скилл не обещает обнаружение всех возможных проблем.

## Разработка и проверка

```powershell
python -m unittest discover -s tests -v
python scripts/fingerprint.py --help
python scripts/install.py --help
```

Тесты проверяют изменение общей зависимости, незакоммиченный код, состав dependency closure, запрет выхода за корень/секретных путей и сохранение ручных правок при установке. Сценарные проверки и ограничения стандартного валидатора описаны в [docs/VALIDATION.md](docs/VALIDATION.md).
