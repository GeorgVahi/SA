# План адаптации SA для Claude Code

Дата: 15 октября 2026.

Статус: D1 (одна кодовая база, два адаптера), D2 (`name: sa`) и D6 (запуск только командой `/sa`) приняты пользователем. Этапы 1–6 внедрены. Этап 7 начат: фикстуры, пробы механизмов и регрессия Codex выполнены, запуски SA в Code tab ждут пользователя — см. [раздел 9](#9-статус-внедрения).

Источники фактов о Claude Code: официальная документация (skills, sub-agents, memory, scheduled-tasks, tools-reference, goal, plugins). Поведение, которое документация не описывает, помечено «проверить» и входит в этап валидации.

Ревью 15 октября 2026: план сверен с исходниками SA, повторно с документацией Claude Code и с бинарником Claude Code 2.1.295 из desktop-приложения на этом Mac. Поправки фактов и найденные пропуски собраны в [разделе 8](#8-ревью-поправки-и-пропуски); разделы 1, 3–5 и 7 дополнены ссылками на него.

## 1. Вывод

Ядро скилла не зависит от платформы: режимы audit/fix/full, роли, контракты артефактов, стандарт доказательств, State schema 2 и оба helper-скрипта. Claude Code может выполнить эту логику без переписывания.

Использовать пакет в текущем виде нельзя: восемь мест опираются на runtime Codex. Без правок скилл не будет обнаружен. Роль, запущенная без явного типа, может унаследовать всю историю координатора (fork). Параллельность сведётся к одной линии, часовые сводки не гарантированы, а роли смогут сами вызвать SA или запустить вложенных агентов. Нужен тонкий слой адаптации, а не новая логика.

Ревью добавило места, которые таблица раздела 3 не покрывает (раздел 8.2): `python` отсутствует на macOS, Edit/Write портят часть кодировок источников, для PDF/Office на этом Mac нет инструментов, фоновые роли простаивают на запросах разрешений, находки могут уйти за пределы `Security Audit/` (memory, транскрипты, Artifact), а конфигурация `.claude/` проверяемого проекта влияет на роли. Слой адаптации остаётся тонким, но часть защит лучше обеспечить механизмами Claude Code, а не строками задания (D6, D7).

## 3. Что завязано на Codex и чем заменить

| # | Место | Codex | Claude Code | Последствие без правки |
| --- | --- | --- | --- | --- |
| 1 | Обнаружение и вызов | `~/.agents/skills/SA`, `$SA`, UI-метаданные `agents/openai.yaml` | `~/.claude/skills/<name>/SKILL.md`, вызов `/<name>`. `~/.agents/skills` не обнаруживается, `openai.yaml` игнорируется | Скилл не появится. `~/.claude/skills` на этом Mac ещё нет. |
| 2 | Чистая роль | `spawn_agent(fork_turns="none")` | Agent с явным `subagent_type: "general-purpose"`; не `fork`, без `isolation: "worktree"`, без `model`. В интерактивных сессиях fork-режим включён по умолчанию и наследует весь диалог | Без явного типа роль может стать форком координатора: независимость ревью нарушена молча. |
| 3 | Слоты | Реальный лимит потоков; «неизвестный лимит → одна линия» | Лимит известен: 20 одновременных сабагентов (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`). 21-й запуск падает с `Concurrent subagent limit reached`, очереди нет | Без указания лимита правило даёт одну линию: fix на 20 файлов идёт строго последовательно. |
| 4 | Вложенные агенты | Роль не запускает агентов по инструкции | Сабагенты по умолчанию могут запускать своих на 3 уровня вглубь | Запрет есть только в тексте задания; его нужно сделать обязательной строкой каждого prompt-а. Жёсткий вариант — настройка глубины (D7). |
| 5 | Ожидание и часовая доставка | `wait_agent` с таймаутом; heartbeat через `automation_update` | Фоновая роль присылает уведомление о завершении. Таймер: `CronCreate` (только в сессии, срабатывает в простое, истекает через 7 дней) или фоновая Bash-команда `sleep`, которая будит сессию при выходе. `PushNotification`, когда пользователь отошёл | Пока фаза длится больше часа, координатор не просыпается и сводку не формирует. Срабатывает ли cron, пока сессия ждёт фоновых агентов, документация не говорит — проверить. Этап 7: не срабатывает; адаптер использует фоновый Bash-`sleep`. |
| 6 | Goal | goal-инструмент, которым управляет координатор | `/goal` задаёт только пользователь, у модели инструмента нет | Безвредно (условие «если доступен»), но координатор может его искать. `goal_owned: false`. |
| 7 | Инструкции проекта | `AGENTS.md` | `CLAUDE.md`. `AGENTS.md` читается автоматически, только если `CLAUDE.md` нет (или включена настройка «claude-md-and-agents-md») | В проекте с обоими файлами `AGENTS.md` пропускается. |
| 8 | Рекурсия | Роли не видят `$SA` как авто-триггер | Сабагенту доступен Skill tool, описание SA срабатывает на «аудит безопасности» | Роль может запустить второй координатор. Нужна явная строка в каждом задании; механизм, который закрывает это без текста, — `disable-model-invocation` (D6). |

Строки 2–8 уточнены в разделе 8.1; поправка к строке 2 относится и к разделу 1.

Второстепенно:

- Путь скилла. В теле `SKILL.md` Claude Code подставляет `${CLAUDE_SKILL_DIR}` — абсолютный путь каталога скилла. Координатор сохраняет его в State (`skill_root`) и передаёт ролям абсолютные пути. После компакции он заново читает нужные references с этого пути.
- Чтение вне рабочего каталога. `~/.claude/skills/sa` лежит вне проекта: Claude Code спрашивает разрешение на такое чтение, а запросы фоновых ролей всплывают в основной сессии (ревью: документация это подтверждает; отказ без диалога приходит в режиме `dontAsk`, от классификатора auto mode и по правилам deny, см. 8.1 и 8.2.4). Нужен allowlist `Read(~/.claude/skills/sa/**)` либо auto mode. Это настройка пользователя, скилл её не меняет.
- Разрешения на Bash/Write ролей в целевом проекте — то же: auto mode или allowlist в `.claude/settings.json`. Отклонённое разрешение даёт неполный результат роли, а не accepted.
- Git. Правило Claude Code «commit/push только по просьбе пользователя» строже текущего «по AGENTS». Действует более строгое.
- README и VALIDATION написаны под Windows/PowerShell и codex-cli. Для Mac нужны `bash`-команды и отдельный раздел проверки Claude Code.
- README требует Python 3.10+, но скрипты используют только возможности 3.9 и проходят на 3.9.6.

## 4. Решения для согласования

**D1. Одна кодовая база или отдельная версия.** Рекомендация: одна. Нейтральное ядро плюс два адаптера: `references/platform-claude-code.md` и `references/platform-codex.md`, куда переезжают нынешние `fork_turns`, `automation_update`, goal и слоты Codex. `SKILL.md` велит прочитать адаптер своей среды. Цена: README требует перепроверять изменение инструкций реальными ролями, значит после правки `SKILL.md`/orchestration Codex-сторону тоже нужно повторно проверить хотя бы discovery и один audit. Альтернатива — ветка только для Claude Code: Codex-пакет не трогается, но две копии будут расходиться.

**D2. Имя и вызов.** Документация Claude Code не запрещает верхний регистр, но и не подтверждает загрузку `SA`; открытый стандарт Agent Skills требует lowercase и совпадения с именем каталога. Рекомендация: `name: sa`, вызов `/sa audit`. При D1 = одна база это меняет и Codex-вызов на `$sa`. Иначе установщик подставляет имя для целевой платформы, и в Claude Code остаётся `SA` после проверки, что такое имя загружается. Ревью: APFS и NTFS по умолчанию не различают регистр, поэтому переименование требует отдельной миграции установки (8.2.8).

**D3. Параллельность.** Предлагается: линий не больше `min(указано пользователем, 20 − активные агенты сессии)`. Без указания — 4 линии: ограничение по стоимости и rate limits, а не по runtime. При `Concurrent subagent limit reached` — дождаться завершения роли, повторять в цикле нельзя. Правила сериализации записи по общим файлам сохраняются.

**D4. Упаковка.** Рекомендация: глобальный скилл `~/.claude/skills/sa` через существующий установщик с `--platform claude`. Plugin (скилл + описания ролей в `agents/*.md` без инструмента Agent) жёстко запретил бы вложенных агентов, но добавляет второй источник правды для заданий ролей. Отложить до опыта реального прогона. Ревью: довод о втором источнике правды слабый. Определение агента может быть тонким: без текста ролей, только запрет инструмента Agent и наследование модели; задания остаются в references. Plugin для этого не нужен, файл в `~/.claude/agents/` ставит тот же установщик. Запрещать ролям весь Skill tool нельзя: `artifact-formats.md` опирается на document-скиллы. Риск — одноимённый агент в `.claude/agents/` проверяемого проекта (8.2.7). Решать после валидации D6 и D7: если они закрывают вложенность и рекурсию, отдельный агент не нужен.

**D5. Часовые сводки.** Рекомендация: таймер на время активного запуска. Основной вариант — `CronCreate` раз в час; prompt задачи читает State и выдаёт сводку только при `active_seconds − last_report_active_seconds ≥ 3600`. Если валидация покажет, что cron не срабатывает, пока сессия ждёт фоновых ролей, — фоновая Bash-команда `sleep` до следующего порога. В финале таймер снимается. `PushNotification` — только если пользователь просил доставку, пока его нет.

Итог этапа 7: основной и единственный таймер — фоновая Bash-команда `sleep` до порога, ID в `heartbeat_id`. CronCreate не используется: пока работает фоновая роль, он не срабатывает, а первый вызов пишет `.claude/scheduled_tasks.lock` и `.git/info/exclude` проверяемого проекта. Сверки с `CronList` нет: после продолжения прежний таймер недействителен, координатор запускает новый.

Ревью: таймер — запасной механизм. Итог каждой фоновой роли и так будит координатора, поэтому порог проверяется при каждом пробуждении; таймер нужен только для фазы без завершений дольше часа. `--resume` восстанавливает неистёкшие задачи cron, но не фоновые Bash-команды; новая сессия без resume начинает без них. Поэтому при продолжении координатор сверяет `heartbeat_id` с `CronList` и не создаёт дубликат. Сработавший cron — ход самого координатора: он сверяется со State и не назначает роли повторно. Текст push содержит только счётчики, без деталей находок (8.2.5).

**D6. Только явный вызов.** Рекомендация: `disable-model-invocation: true` во frontmatter. По документации Claude не может вызвать такой скилл сам, и он не подгружается в сабагенты; в коде 2.1.295 такие скиллы исключены из списка Skill tool. Рекурсия (строка 8) закрывается механизмом, а не строкой задания, и дорогой запуск не начнётся от случайной фразы «проверь безопасность». Цена: просьба без `/sa` скилл не запустит, а description перестаёт влиять на авто-вызов. Это совпадает с явным `$SA` в Codex. Что вызов SA из роли действительно отклоняется, документация не говорит — проверить. Этап 7 (прогон 0): Skill `sa` без команды пользователя отклоняется механизмом и у координатора, и у роли.

**D7. Жёсткие ограничения среды.** Рекомендовать в README, но не включать скриптом: все они действуют на сессию или пользователя целиком. Варианты:

- `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` — вложенность выключена. Запрет `Agent` через `permissions.deny` не подходит: он остановит и координатора. Этап 7 (прогон 0): при `=1` у ролей нет инструмента Agent; без переменной вложенный агент создаётся.
- `CLAUDE_CODE_FORK_SUBAGENT=0` или правило deny `Agent(fork)` — форк невозможен при любом выборе координатора.
- `/sandbox` — сабагенты используют ту же конфигурацию. Песочница покрывает только Bash, PowerShell и Monitor: запись вне рабочего каталога и сеть, кроме allowlist (по умолчанию пустого). Read, Edit, Write, WebFetch, WebSearch и MCP она не ограничивает. Доступен ли localhost для локальных тестов — проверить.
- Правила deny для WebFetch, WebSearch и MCP на время запуска.
- Hook из frontmatter скилла: регистрируется при вызове и остаётся до конца сессии. PreToolUse на Agent может отклонять вызов без `general-purpose`, с `fork`, `model` или `isolation`. Срабатывает ли он на вызовы внутри сабагентов — проверить. Этап 7 (прогон C): PreToolUse-hook видит вызовы внутри сабагентов. Это часть самого скилла, но она переживает запуск SA, поэтому hook ничего не делает, когда в State нет активного запуска.

В начале запуска координатор сообщает, какие из ограничений не включены, и не считает строку задания их полной заменой.

**D8. Форматы без инструментов на Mac.** Варианты: (а) честный blocker для PDF, Office и сканов, пока пользователь сам не поставит инструменты; (б) раздел README с необязательными инструментами и правилом, как роль их находит. Рекомендация: (а) по умолчанию, (б) как документация. Скилл ничего не устанавливает (8.2.3).

   - audit на 2–3 эндпоинтах: свежие inventory/auditor/reviewer, разные agent ID, тип `general-purpose`, prompt-ы без истории координатора;
   - fix с общим дефектом на двух источниках, параллельные линии и сериализация общего файла;
   - full;
   - часовая сводка на укороченном интервале: срабатывает ли cron, пока роли работают в фоне; при неудаче — таймер на Bash;
   - продолжение после `/compact`;
   - доказательства dispatch по транскриптам сабагентов: тип, первое сообщение без истории координатора, разные ID, нет вызовов Agent и SA внутри ролей, токены на роль (8.2.14);
   - роль пытается вызвать SA и запустить агента — оба вызова отклонены механизмом, а не только текстом (D6, D7);
   - заведомо неразрешённая команда в фоновой роли: роль возвращает blocked (8.2.4);
   - fix на источниках cp1251, UTF-16 LE и со смешанными CRLF/LF: побайтовая сохранность (8.2.2); по одному DOCX, XLSX и PDF — запись или конкретный blocker (8.2.3);
   - фикстура с `.claude/agents/general-purpose.md` и hook в `.claude/settings.json` проверяемого проекта (8.2.7);
   - рестарт сессии при работающей фоновой роли: судьба роли, поздний итог, частичная запись (8.2.11);
   - регрессия Codex-стороны на этом же Mac через встроенный `codex` (8.2.15).

   Результаты записать новым разделом `docs/VALIDATION.md` с версией Claude Code (8.2.18).

## 6. Что не меняется

Четыре роли fix, две фазы аудита на эндпоинт, свежий независимый ревьюер, 12 категорий и стандарт доказательств, State schema 2 и миграция schema 1, контракт форматов источников, четырёхколоночная итоговая таблица, отсутствие числового порога оценки, границы безопасности. Формат `fingerprint.py` и его схема.

## 7. Риски

- Стоимость: контекст роли в desktop до чтения скилла — около 50 тыс. токенов (системный prompt и описания инструментов; замер этапа 7 на 2.1.295, см. VALIDATION). Затем роль заново читает `SKILL.md` и 3–5 references — по оценке ещё 30–40 тыс. токенов. Каждый вызов модели внутри роли перечитывает этот контекст из кеша. Fix на N файлов — минимум 4N ролей.
- Независимость в Claude Code держится на двух условиях: явный тип `general-purpose` и отсутствие истории в тексте задания. Жёсткая защита — запрет `Agent(fork)` в настройках проекта или `CLAUDE_CODE_FORK_SUBAGENT=0`; это решение пользователя.
- Фоновые роли и запросы разрешений: при отклонённом разрешении роль может вернуть неполный результат — координатор должен считать это blocker, а не accepted.
- Лимиты тарифа, сон Mac и закрытие приложения обрывают длинный `full` посреди фазы. Это штатный сценарий продолжения, а не редкость (8.2.11, 8.2.17).
- Поведение частично задаётся удалёнными флагами (глубина вложенности, проверка лимита сабагентов) и меняется без обновления пакета SA. Валидация привязана к версии Claude Code (8.2.18).
- Находки по умолчанию оседают вне `Security Audit/`: в транскриптах и, при неосторожности координатора, в memory или Artifact (8.2.5).

## 8. Ревью: поправки и пропуски

Источники ревью: исходники SA; документация Claude Code на code.claude.com/docs (skills, sub-agents, tools-reference, scheduled-tasks, sessions, sandboxing, env-vars, memory, goal), прочитанная 15 октября 2026; строки бинарника Claude Code 2.1.295 из desktop-приложения — там, где документация молчит. Сведения из бинарника относятся только к этой версии и помечены «в коде 2.1.295».

### 8.1 Поправки к разделам 2–3

| Место | Уточнение |

### 8.2 Пропуски

Критично — ломает запуск, независимость или конфиденциальность:

1. **`python` нет на macOS.** `references/artifacts.md:69-70` и README вызывают `python …/fingerprint.py`. На этом Mac есть только `/usr/bin/python3` (3.9.6), `python` отвечает «command not found». Каждая аудиторская роль наткнётся на это. → Этапы 1, 4 и 6: нейтральная формулировка в references, конкретная команда в адаптере, allowlist по `python3`.
2. **Edit/Write не сохраняют часть кодировок.** Прежняя валидация использовала источники в UTF-16 LE, cp1251 и со смешанными CRLF/LF. Edit откажется править cp1251; роль либо остановится, либо перейдёт на Write, который сохранит файл в UTF-8 и потеряет исходные bytes. Смешанные переводы строк в коде 2.1.295 нормализуются. → Адаптер: исходники, кроме UTF-8 и UTF-16 LE с BOM с едиными переводами строк, менять только скриптом (`python3`, явный codec, `newline=''`) с побайтовой проверкой сохранённого префикса. Edit/Write — для собственных артефактов SA.
3. **На этом Mac нечем записать PDF и Office.** Прежние проверки форматов шли на bundled runtime Codex (pypdf, openpyxl, render_docx/soffice). Здесь у `python3` нет pypdf, openpyxl, python-docx и PIL; нет soffice, poppler, qpdf и tesseract. Read в Claude Code читает PDF и изображения, но записать результат в PDF или скан нечем; DOCX и XLSX — только через ZIP+XML стандартной библиотеки. Устанавливать зависимости скилл не вправе. → D8; адаптер проверяет возможности формата до назначения линии.
4. **Роли простаивают на разрешениях.** Запрос фоновой роли ждёт ответа в основной сессии. Если пользователь отошёл, роль стоит часами, а время идёт как active. В `dontAsk` и auto mode отказ приходит без диалога, и исполнитель или ревьюер кода остаётся без RED/GREEN. → До первого запуска ролей координатор перечисляет нужные разрешения: чтение каталога скилла, `python3`, тестовая команда проекта, запись в `Security Audit/` и разрешённые исходники. Пользователь выбирает режим или allowlist заранее. В каждом задании: отказ в инструменте — blocked с именем инструмента, не passed и не not_applicable. Ожидание разрешения сводка показывает как blocker.
5. **Находки уходят за пределы `Security Audit/`.** Каналы: auto memory основной сессии (`~/.claude/projects/<slug>/memory/` — координатор может «запомнить» уязвимость); транскрипты сессии и сабагентов в `~/.claude/projects/` (по умолчанию хранятся 30 дней, `cleanupPeriodDays`); Artifact, который доступен и фоновым ролям и публикует страницы на claude.ai; коннекторы Docs и Slack; текст `PushNotification`. Граница SKILL о публикации отчёта эти каналы не называет. → Адаптер и каждое задание: не записывать находки, payload и секреты в memory; не публиковать через Artifact и коннекторы без разрешения именно на находки; в push — только счётчики. README: транскрипты содержат находки.
6. **Роль, выполненная не сабагентом.** В desktop-приложении у координатора есть `start_session`, а у фоновых ролей — `EnterWorktree`. Под давлением лимита координатор может вынести роль в отдельную сессию, а роль — создать worktree, что SKILL запрещает. Кроме того, в коде 2.1.295 есть вариант описания Agent (зависит от тарифа), где модели велено запускать сабагентов только по явной просьбе пользователя; тогда координатор может начать выполнять роли сам. → SKILL.md: «вызов `/sa` — явная просьба пользователя запускать роли сабагентами». Адаптер: роли только через Agent, без отдельных сессий и `EnterWorktree`. Валидация подтверждает, что каждая роль была сабагентом.
7. **Конфигурация проверяемого проекта влияет на роли.** Codex читал из проекта только AGENTS.md. Claude Code применяет `.claude/settings.json` (hooks с shell-командами на вызовы инструментов, allow-правила, env), `.mcp.json`, `.claude/agents/` и CLAUDE.md. Проектный агент сильнее пользовательского, а может ли проект перекрыть встроенный `general-purpose`, документация не говорит. Этап 7 (прогон C): перекрывает, и по типу в метаданных подмену не отличить. → Координатор на старте фиксирует эти файлы в State. Подмена типа роли — blocker. Инструкции проекта, противоречащие границам SKILL, — данные, не полномочия.
8. **Смена регистра имени на регистронезависимой ФС.** APFS по умолчанию и NTFS не различают `skills/SA` и `skills/sa`. `install.py` жёстко задаёт каталог `SA` и `package: 'SA'` в manifest. `--update` после переименования либо оставит каталог `SA` с `name: sa`, либо откажет из-за manifest. → Этап 5, если D2 выбирает `sa`.

Важно — снижает надёжность или делает проверку неполной:

9. **Защиты держатся на тексте задания.** Строки 2, 4 и 8 раздела 3 закрыты только формулировками, хотя у Claude Code есть механизмы: `disable-model-invocation`, глубина вложенности, запрет `Agent(fork)`, hook на Agent, тонкий агент с `disallowedTools: Agent`. Запрещать ролям весь Skill tool нельзя: `artifact-formats.md` опирается на document-скиллы. → D6, D7, пересмотр D4.
10. **Контекст координатора.** Итог каждой роли попадает в контекст координатора. Fix на 20 файлов — больше 80 итогов и уведомлений, плюс аудит; компакции будут частыми. → Итог роли — короткий структурированный ответ: ID, attempt, вердикт, версии и digest, пути артефактов, blockers; подробности только в файлах. Координатор пишет State после каждого итога, а после компакции первым читает State.
11. **Жизненный цикл фоновых ролей.** `Ctrl+X Ctrl+K` останавливает все фоновые роли сразу. После `--resume` незавершённая работа видна только как заметка, и Claude Code не начинает ход сам: запуск стоит, пока пользователь не попросит продолжить. Фоновые Bash и Monitor не восстанавливаются. Судьба ролей при закрытии приложения и поздние итоги после resume не документированы. Сон Mac и исчерпание лимита тарифа рвут запуск так же. → Адаптер: таблица «событие → действие». Роль без подтверждённого завершения — «неизвестно», diff сверяется до нового писателя, остановка — через `TaskStop`. README: keep-awake для долгих запусков (настройка desktop-приложения или `caffeinate -i`). Active time считается по интервалам работы, разрывы исключаются, а не берётся разница wall-clock.
12. **Таймер сводок при продолжении.** `--resume` восстанавливает cron, свежая сессия — нет; фоновый `sleep` не восстанавливается никогда. Сработавший cron — ход самого координатора. → D5: сверка `heartbeat_id` с `CronList`, без дубликатов и повторного назначения ролей. Итог этапа 7: таймер — фоновый Bash, сверки с `CronList` нет; после продолжения координатор запускает новый таймер.
13. **Сетевые инструменты ролей.** Роли наследуют WebFetch, WebSearch и MCP-коннекторы. Поиск CVE может отправить во внешний сервис имена пакетов, маршруты или фрагменты кода, а коннектор — выполнить внешнее действие. Если прежние прогоны опирались на sandbox Codex, в Claude Code песочница по умолчанию выключена. → D7; в задании: внешние запросы только с публичными данными, без кода и находок.
14. **Доказательства dispatch.** Валидация Codex опиралась на runtime-события. В Claude Code источник — транскрипты `~/.claude/projects/<project>/<session>/subagents/agent-<id>.jsonl`: тип, prompt, модель, вызовы инструментов, расход токенов. Формат внутренний и может меняться, поэтому проверка разбирает его терпимо. В `.verification/` — только отфильтрованные метаданные, сырые транскрипты в Git не попадают.
15. **Окружение валидации.** `claude` и `codex` не в PATH: CLI лежит в `~/Library/Application Support/Claude/claude-code/<версия>/…/claude`, Codex — внутри `ChatGPT.app`. Поэтому регрессию Codex-стороны из D1 (discovery через `codex app-server` / `skills/list`) можно выполнить на этом же Mac. В `-p` fork-режим выключен, AskUserQuestion нет, разрешения работают иначе, а init-событие не перечисляет скиллы (этап 7: неверно для 2.1.295 — `sa` есть в `skills` и `slash_commands`; модельный ход в `-p` требует отдельного входа в CLI). `-p` годится для отдельных проверок; discovery смотреть через `/skills`, workflow — в той поверхности, где SA будут запускать (Code tab desktop-приложения).

Желательно:

16. **Worktree-сессии desktop-приложения.** Если сессия работает в worktree, созданном приложением, `Security Audit/` и фиксы окажутся в его ветке, а продолжение из основной копии State не увидит. → Координатор пишет в State фактический корень и признак worktree и предупреждает пользователя.
17. **Стоимость в цифрах.** references — 132 КБ русского текста, из них `artifacts.md` — 50 КБ; роль remediation читает около 120 КБ до начала работы. Длинный `full` может упереться в лимит тарифа посреди фазы — это сценарий 11. → Валидация меряет токены на роль по транскриптам; README даёт порядок стоимости; ETA не включает паузы лимита в active time.
18. **Привязка к версии.** Часть поведения Claude Code задаётся удалёнными флагами и меняется без обновления SA. → VALIDATION указывает версию Claude Code. После обновления CLI повторить минимум: discovery, свежесть роли, запрет вложенности и вызова SA из роли.
